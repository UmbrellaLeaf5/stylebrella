# Форматирование Kotlin

[English version](../../../en/code-style/kotlin/formatting.md)

Эта страница дополняет [общие правила форматирования](../formatting.md) правилами Kotlin. Она охватывает `.kt` и `.kts`, включая скрипты Gradle. См. [линтинг Kotlin](linting.md). Фрагменты предназначены для приёмочных тестов.

## Оформление и движок

Используйте UTF-8, CRLF и перенос в конце файла. Удаляйте пробелы в конце строк. Если вызов или сигнатура переносится, каждый аргумент или параметр и закрывающую скобку ставьте на отдельную строку. Ставьте пробелы после запятых и вокруг операторов равенства, сложения и вычитания, умножения и деления, а также сравнения. Учитывайте участки с отключённым форматированием. Порядок импортов: обычные, затем `java`, `javax`, `kotlin` и импорты с псевдонимами. Переходите на импорт со звёздочкой при пяти именах или трёх членах типа, только если сохраняется разрешение имён.

Встроенный пресет не должен зависеть от IntelliJ или настроек `ij_*`. Примеры результата задают требования. Форматтер Kotlin выбирается после сравнения кандидатов, включая ktfmt, если он может выполнить требования; наличие ktlint в предварительной версии не означает окончательного решения о совместимости. Второй проход не должен менять результат.

До:

```kotlin
fun calculateAndPersist(entityWithConfiguration: OrderEntity, selectedItem: ItemEntity?, evaluationTime: Instant): State {
    return calculate(entityWithConfiguration,selectedItem,evaluationTime)
}
```

После, если переход к телу-выражению сохраняет сигнатуру:

```kotlin
fun calculateAndPersist(
  entityWithConfiguration: OrderEntity,
  selectedItem: ItemEntity?,
  evaluationTime: Instant,
) = calculate(entityWithConfiguration, selectedItem, evaluationTime)
```

## Тела-выражения

Переписывайте блок, эквивалентный одному выражению, в форму `= expression`, удаляя ставший лишним `return`. Опускайте явный тип результата, только если сохраняются выведенный тип, публичный контракт, поведение переопределений и семантика `Unit`. Не переписывайте ранние возвраты и возвраты с меткой, контракты и неоднозначные случаи. Например, `fun count(): Int { return items.size }` превращается в `fun count() = items.size`, если известно, что `items.size` имеет тип `Int`. Явный более общий тип публичного результата может потребоваться сохранить.

## Пустые строки

- Отделяйте одной пустой строкой ветви `when` с телом-блоком, категории параметров конструктора и объявления с комментариями или аннотациями.
- Оставляйте `else if`, `else` и `catch` на отдельной строке. Тела из одной инструкции могут оставаться без фигурных скобок; форматтер их не навязывает.

До:

```kotlin
val processor = Processor()
processor.init(config)
if (config.enabled) {
  processor.start()
} else {
  processor.stop()
}
```

После:

```kotlin
val processor = Processor()
processor.init(config)

if (config.enabled) {
  processor.start()
}

else {
  processor.stop()
}
```

## Разделители и приватные методы

Используйте `//` для общих разделителей и структурных комментариев. KDoc должен примыкать к объявлению или его аннотациям. В [линтинге Kotlin](linting.md#mark-порядок-методов-и-документация) определено, какие методы считаются приватными.

```kotlin
class Reader {

  fun read() = source.read()

  // (no private methods)
}
```
