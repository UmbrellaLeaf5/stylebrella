# Форматирование Python

[English version](../../../en/code-style/python/formatting.md)

Эта страница дополняет [общие правила форматирования](../formatting.md) правилами Python. Она охватывает `.py`; ноутбуки и отдельные файлы конфигурации отложены. См. [линтинг Python](linting.md). Примеры предназначены для приёмочных тестов или показывают выдержки из них.

## Оформление и импорты

Используйте LF и двойные кавычки, если смена кавычек сохраняет значение литерала. Ruff — базовый форматтер Python и инструмент сортировки импортов. Не запускайте следом Black или isort. Группируйте импорты в порядке: стандартная библиотека, сторонние пакеты, локальные модули; между группами оставляйте пустую строку. Сохраняйте привязку комментариев и порядок импортов, которые нельзя безопасно переставить. Диагностика порядка импортов относится к проверке форматирования, даже если в Ruff за сортировку отвечает правило `I`.

До:

```python
from app import run
import os
def main():
    run('example', os.environ)
```

После:

```python
import os

from app import run


def main():
  run("example", os.environ)
```

## Пустые строки

- После docstring функции или класса ставьте пустую строку перед первой инструкцией. Если тело состоит только из docstring, пустая строка в конце тела не нужна.
- Помимо общих правил управляющих конструкций, на границе инструкций одного уровня ставьте пустую строку перед `while`, `try`, `finally`, `with`, `raise`, `assert` и `continue`. Отделяйте заголовки `elif`, `else`, `except` и `finally` от предшествующего блока. Не разрывайте однострочное тело и не ставьте пустую строку перед его единственной инструкцией. Глубоко вложенные однострочные конструкции могут оставаться компактными.
- Последовательность отдельных присваиваний полям после объявления объекта начинается с пустой строки. Для инициализации, за которой следует вызов метода того же объекта, действуют общие правила группировки.
- Сохраняйте комментарии с категориями в списке параметров конструктора и не вставляйте там пустых строк. Комментарии в конце строки начинаются с `# ` и остаются рядом со своим кодом.

До:

```python
def configure(config: Config) -> None:
  announce()
  filter_ = Filter()
  filter_.init(config)
  if config.enabled:
    filter_.start()
  return
```

После:

```python
def configure(config: Config) -> None:
  announce()

  filter_ = Filter()
  filter_.init(config)

  if config.enabled:
    filter_.start()

  return
```

## Разделители и приватные методы

Используйте `#` для общих разделителей и структурных комментариев. В [линтинге Python](linting.md#mark-порядок-методов-и-документация) определено, какие методы считаются приватными.

До:

```python
class Reader:
  def read(self) -> str:
    return self._read()
  def _read(self) -> str:
    return self.source.read()
```

После:

```python
class Reader:

  def read(self) -> str:
    return self._read()

  # MARK: Private Helpers
  # --------------------------------------------------

  def _read(self) -> str:
    return self.source.read()
```

Второй проход форматтера не должен вносить изменений. Если вывод Ruff расходится с примером оформления, зафиксируйте расхождение и устраните его до объявления поддержки; не выпускайте два прохода, которые отменяют изменения друг друга.
