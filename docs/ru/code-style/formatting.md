# Общие правила форматирования

[English version](../../en/code-style/formatting.md)

Целевая спецификация пресета `template`. Команда `format` применяет эти изменения, `format --check` проверяет их необходимость без записи, а `check` объединяет эту проверку с [линтингом](linting.md). Дополнительные правила: [Python](python/formatting.md), [Kotlin](kotlin/formatting.md), [C++](cpp/formatting.md). Примеры показывают фрагменты кода: `⏎` — перенос, `⏎⏎` — одна пустая строка. В приёмочных тестах запускайте весь форматтер дважды: второй проход ничего не меняет.

## Отступы и переносы

Используйте отступ в два пробела и ориентир в 100 столбцов. Переносите длинные сигнатуры и вызовы с висячим отступом. Не разрывайте неделимый токен и не меняйте значение литерала. Разделители и отступы продолжения зависят от языка.

| Язык   | До                           | После                      |
| ------ | ---------------------------- | -------------------------- |
| Python | `if ready:⏎    send()`       | `if ready:⏎  send()`       |
| Kotlin | `if (ready) {⏎    send()⏎}`  | `if (ready) {⏎  send()⏎}`  |
| C++    | `if (ready) {⏎    send();⏎}` | `if (ready) {⏎  send();⏎}` |

Если вызовы выходят за целевую ширину, используйте следующую форму (имена для краткости сокращены):

| Язык   | До                               | После                                    |
| ------ | -------------------------------- | ---------------------------------------- |
| Python | `run(config, settings, logger)`  | `run(⏎  config,⏎  settings,⏎  logger,⏎)` |
| Kotlin | `run(config, settings, logger)`  | `run(⏎  config,⏎  settings,⏎  logger,⏎)` |
| C++    | `run(config, settings, logger);` | `run(⏎  config,⏎  settings,⏎  logger);`  |

## Пустые строки на верхнем уровне и между членами класса

Применяйте правило Ruff во всех трёх языках: две пустые строки после последнего блока импортов или включений и между блоками кода верхнего уровня, в том числе с каждой стороны разделителя между равноправными объявлениями. В классе или функции допускается не более одной пустой строки; ставьте её перед первым методом и между членами класса, которые нужно разделить. Правила на одной границе не суммируются. Аннотации, декораторы и документация остаются при своих объявлениях.

| Язык   | До                                         | После                                        |
| ------ | ------------------------------------------ | -------------------------------------------- |
| Python | `import time⏎def run(): ...`               | `import time⏎⏎⏎def run(): ...`               |
| Kotlin | `import app.Clock⏎fun run() = clock.now()` | `import app.Clock⏎⏎⏎fun run() = clock.now()` |
| C++    | `#include "Clock.hpp"⏎void run();`         | `#include "Clock.hpp"⏎⏎⏎void run();`         |

## Группы инструкций

Отделяйте группы локальных объявлений пустой строкой, если соседние инструкции относятся к другим группам. Последовательные объявления могут оставаться рядом. Объявление и следующие непосредственно за ним операции над тем же объектом могут оставаться в одной группе; посторонняя инструкция или явно отмеченная граница завершает группу. Соседние поля оставляйте вместе, если комментарий или аннотация не открывает новую группу. Сохраняйте явно выделенные границы и не угадывайте смысловые связи. После многострочной инструкции ставьте пустую строку перед следующей на том же уровне. Исключения описаны в правилах языков.

| Язык   | До                                                      | После                                                   |
| ------ | ------------------------------------------------------- | ------------------------------------------------------- |
| Python | `announce()⏎filter_ = Filter()⏎⏎filter_.init(config)`   | `announce()⏎⏎filter_ = Filter()⏎filter_.init(config)`   |
| Kotlin | `announce()⏎val filter = Filter()⏎⏎filter.init(config)` | `announce()⏎⏎val filter = Filter()⏎filter.init(config)` |
| C++    | `announce();⏎Filter filter;⏎⏎filter.init(config);`      | `announce();⏎⏎Filter filter;⏎filter.init(config);`      |

## Пустые строки в управляющих конструкциях

Отделяйте `if` и `for` от соседних инструкций, в том числе после однострочного тела без скобок. Разделяйте ветви условий и обработчики исключений пустой строкой. Ставьте пустую строку перед `return`, кроме случаев, когда он единственная инструкция блока или часть однострочного тела управляющей конструкции. Не добавляйте пустую строку перед закрывающим разделителем блока только потому, что предыдущая инструкция была управляющей. Другие границы и синтаксис определены в правилах языков.

| Язык   | До                           | После                         |
| ------ | ---------------------------- | ----------------------------- |
| Python | `  send()⏎  return result`   | `  send()⏎⏎  return result`   |
| Kotlin | `  send()⏎  return result`   | `  send()⏎⏎  return result`   |
| C++    | `  send();⏎  return result;` | `  send();⏎⏎  return result;` |

## Оформление MARK и разделителей

После префикса комментария и пробела ставьте ровно 50 дефисов. Добавляйте отсутствующий разделитель на однозначной границе между функциями одного уровня. Строка MARK располагается прямо над разделителем. Вокруг всего блока действуют обычные правила пустых строк для верхнего уровня или членов класса. Исправляйте длину только у распознанных разделителей; обычные комментарии сохраняйте. Форматтер не сочиняет описания MARK и не меняет счётчики `[group:N]`.

| Язык   | До                             | После                                                                       |
| ------ | ------------------------------ | --------------------------------------------------------------------------- |
| Python | `# MARK: Read input⏎⏎# ----`   | `# MARK: Read input⏎# --------------------------------------------------`   |
| Kotlin | `// MARK: Read input⏎⏎// ----` | `// MARK: Read input⏎// --------------------------------------------------` |
| C++    | `// MARK: Read input⏎⏎// ----` | `// MARK: Read input⏎// --------------------------------------------------` |

## Секция Private Helpers

В конкретном классе с публичными методами вставляйте один блок `MARK: Private Helpers` перед приватными методами, если они есть. Удаляйте дублирующиеся заголовки секции и устаревшие комментарии-заглушки. Если приватных методов нет, удаляйте заголовок секции вместе с разделителем и ставьте вместо них обычный комментарий `(no private methods)`. Если секции не было, добавляйте комментарий после публичных методов. Интерфейсы и классы, используемые только как DTO, освобождены от правила. Привязывайте заголовок к приватным объявлениям; в C++ сохраняйте действующий уровень доступа. Не переставляйте методы: о нарушении порядка сообщает [линтер](linting.md#порядок-приватных-методов).

| Язык   | До (в классе нет приватных методов)                                              | После                     |
| ------ | -------------------------------------------------------------------------------- | ------------------------- |
| Python | `# MARK: Private Helpers⏎# --------------------------------------------------`   | `# (no private methods)`  |
| Kotlin | `// MARK: Private Helpers⏎// --------------------------------------------------` | `// (no private methods)` |
| C++    | `// MARK: Private Helpers⏎// --------------------------------------------------` | `// (no private methods)` |
